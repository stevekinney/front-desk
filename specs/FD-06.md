# FD-06: Ticket priority end to end

**Size:** M

## Background

Teammates triage by eye today. They want to mark a ticket's priority and see it at a glance. Finance wants it too, in the nightly export of resolved tickets (`legacy/export/nightly-csv.js`), so they can see what urgent work costs.

## Acceptance criteria

1. Every ticket has a `priority`: one of `low`, `normal`, `high` or `urgent`.
2. Tickets that arrive by email, including every ticket that exists today, have `normal` priority.
3. `PATCH /api/tickets/{id}/priority` with `{ "priority": ... }` sets it and responds with the updated ticket. An unknown priority is rejected with `400`, and an unknown ticket gets `404`. Changing the status or the assignee leaves the priority alone.
4. `GET /api/tickets` accepts an optional `priority` query parameter that limits the list to that priority.
5. In the web app:
   - Inbox rows for high and urgent tickets show "High" or "Urgent". Normal and low tickets show no priority label.
   - The ticket page has a "Priority" select with the four values, and changing it saves right away.
6. The nightly export has a `priority` column after all the existing columns. Every existing column keeps its name, its position and its values.
7. The OpenAPI contract describes the field, the parameter and the new operation, and the generated types match it.
