# FD-05: Create a ticket from the web

**Size:** M

## Background

Some customers phone in or stop by the counter. Today the only way to get their request into Front Desk is to email it to ourselves. Teammates need to open a ticket on a customer's behalf from the web app.

## Acceptance criteria

1. The inbox has a "New ticket" control. It opens a form with these labeled fields: "Customer email", "Customer name" (optional), "Subject" and "Message", and a "Create ticket" button.
2. `POST /api/tickets` creates a ticket. The request body is `{ "customerEmail": string, "customerName"?: string, "subject": string, "body": string }`. The response is `201` with the new ticket, in the same shape `GET /api/tickets/{id}` uses for a ticket.
3. The new ticket is `open` and unassigned, and its SLA starts when it is created. Its thread has one message: the customer's, inbound, with the text from "Message". It shows up in the inbox like a ticket that arrived by email.
4. If a customer with that email already exists, ignoring case, the ticket is theirs. Otherwise a new customer is created.
5. A missing or invalid email, or a blank subject or message, is rejected with `400` and creates nothing. The form stays open and the teammate can correct it.
6. The OpenAPI contract describes the new operation, and the generated types match it.
7. After creating the ticket, the web app shows its ticket page.
