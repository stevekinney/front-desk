# FD-09: Auto-tag incoming mail

**Size:** M

## Background

Teammates tag every new ticket by hand with one of five category tags: `billing`, `shipping`, `account`, `printing` or `spam`. That is slow, and the newest tickets in the inbox haven't been tagged at all. Use the mail already in `inbox/`, and the tags teammates gave it (`apps/api/src/seed/seed-data.ts`), to build rules that tag new mail automatically.

## Acceptance criteria

1. When an email opens a new ticket, the ticket gets the category tag that fits it. This happens however the mail arrives: the poller, `npm run mail:drop`, or the "Simulate incoming email" button.
2. Mail that fits no category gets no category tag.
3. Unsolicited offers, prize notices and other bulk mail get `spam`.
4. Replayed against the seeded inbox, the rules agree with the teammates' category tags on at least 90% of the tickets the teammates tagged, and they tag the tickets nobody has tagged yet.
5. A follow-up email on an existing ticket never removes or replaces tags a teammate set.
6. Other tags, such as `urgent`, and the existing automation rules keep working as they do today.
7. `npm run check` stays green.
