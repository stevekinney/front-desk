# FD-10: Collapse `state` into `status`

**Size:** M

## Background

The `tickets` table has two columns for the same thing: `status` (`open`, `pending`, `closed`) and an older `state` (`active`, `on_hold`, `resolved`). Every status change writes both. Nothing in the TypeScript code reads `state`, and keeping the two in step is one more thing to get wrong. We want a single column.

## Acceptance criteria

1. The `tickets` table has a `status` column and no `state` column.
2. Existing databases are migrated when the app starts. The column goes away, and no ticket or status is lost.
3. Status changes still work everywhere they happen today: in the API, the web app, and the mailroom (for example, a customer's reply reopening a ticket).
4. Everything that consumes ticket data today, inside or outside this repository, keeps getting exactly what it gets now.
5. `npm run check` stays green.
