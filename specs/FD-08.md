# FD-08: Port the automation rules to TypeScript

**Size:** L

## Background

The mailroom runs five automation rules from `legacy/rules/`: `auto-close-stale`, `escalate-vip`, `tag-billing`, `assign-round-robin` and `reopen-on-reply`. All new work happens in the TypeScript API, and the rules need to move there before the mailroom can be retired. Each rule has golden cases in `fixtures/rules/<name>.json`. `npm run rules:parity -- <name>` checks a rule against them.

This item is the port. Switching the mailroom over to the ported rules is a separate, later change.

## Acceptance criteria

1. Each rule has a TypeScript version at `apps/api/src/rules/<name>.ts`. It exports `rule`, or a default export, with the same shape as the mailroom's: `{ name, when(ticket), run(ticket, ctx, cb?) }`. `run` may call `cb` or return a promise.
2. `npm run rules:parity -- <name>` reports every golden case matching for the TypeScript version.
3. The ported rules don't import anything from `legacy/`, directly or through `apps/api/src/legacy-adapter.ts`. They get everything they need from `ticket` and `ctx`.
4. The mailroom's rules and the golden fixtures are unchanged, and the mailroom versions still match every golden case.
5. `npm run check` stays green.
